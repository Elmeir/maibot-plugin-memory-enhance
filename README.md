# 记忆增强（maibot-plugin-memory-enhance）

> 在宿主长期记忆之上补齐检索缺口与记录能力：可跨聊天流检索、可纳入「事实声明」与「日记」，并给模型一个随时写日记的工具。

- 插件 ID：`github.elmeir.memory-enhance`
- 宿主要求：MaiBot >= 1.2.5（maibot-plugin-sdk >= 2.8.1）
- 依赖：无（仅标准库与宿主能力）
- 作者：[Elmeir](https://github.com/Elmeir) ｜ License：[MIT](LICENSE)
- 版本：见 [_manifest.json](_manifest.json) ｜ 变更见 [CHANGELOG.md](CHANGELOG.md)

## 功能

- **检索工具两种接入方式（可切换）**：
  - 「新增工具」（默认）：`search_memory`——始终随工具列表提供，装上即用；插件自动从 planner 列表移除内置 `query_memory`（避免两个相似工具并存）；
  - 「替换原生」：`query_memory` 同名接管——先在宿主关闭内置记忆检索后，planner 视角零变化（工具名不变）；
- **跨聊天流检索（三态可选）**：关闭（默认）= 仅当前聊天流；仅群聊 = 当前流 + 全部群聊（不含其它私聊）；全部 = 全部会话（含私聊）；
- **事实声明检索**：只读直读记忆库的「事实」表（宿主内置检索不含它），带可信度与证据条数；
- **日记**：`write_diary` 工具——模型随时把想记住的内容写成日记（本插件自有数据库，自动归属写入时的聊天流），检索时以 `[日记]` 前缀回看；
- **日记管理指令**：`/日记` 查看当前聊天流的日记（真实日记口吻），`/删日记 [编号]` 查看（跨流全部）/删除日记；无权限时静默不回复；
- **经历/事件检索（可选，默认关）**：经历类记忆经宿主聚合管线检索（较重，需要时开启）。

## 安装

```bash
cd /你的部署目录/plugins
git clone https://github.com/Elmeir/maibot-plugin-memory-enhance maibot-plugin-memory-enhance
```

目录名请保持 `maibot-plugin-memory-enhance`（改名会丢失已生成的 `config.toml`）。

**默认模式无需任何宿主配置**，装上重启即可（自动使用 `search_memory`）。

若想用「替换原生」模式（工具名保持 `query_memory`）：在宿主 WebUI 的**「记忆」页关闭「启用记忆检索」**
（对应配置 `a_memorix.integration.enable_memory_query_tool`），并在插件配置「工具」页签开启「替换原生」——
否则插件同名工具会被内置版跳过（宿主日志出现「检测到重复工具名」告警，插件加载时也会给出提示）。

## 配置

首次启动自动生成 `config.toml`；全部配置项在 WebUI 均有中文标签与小字说明：

| 页签 | 配置项 | 默认 | 说明 |
|---|---|---|---|
| 数据源 | 日记 | 开 | 模型写下的日记（本插件自有数据库） |
| 数据源 | 段落与关系 | 开 | 长期记忆的段落与图谱关系检索 |
| 数据源 | 事实声明 | 开 | 只读直读记忆库「事实」表；库不存在时本路自动跳过并提示一次 |
| 数据源 | 经历与事件 | 关 | 经历类记忆（聚合管线，检索较重） |
| 检索 | 跨聊天流检索 | **关闭** | 关闭 = 仅当前聊天流（尊重记忆过滤策略）；仅群聊 = 当前流 + 全部群聊（不含其它私聊，群多时略慢）；全部 = 全部会话 |
| 工具 | 替换原生 query_memory | **关** | 关 = `search_memory` 新增工具；开 = 同名接管（需先关宿主内置） |
| 日记 | 日记工具 | 开 | 提供 `write_diary`；关闭后工具不提供，已记录内容保留 |

全部数据源关闭时工具直接返回失败提示，不空转。

「宿主检索参数」页签为**只读展示**：显示宿主 A_Memorix 的阈值与条数设置及各自的修改入口
（本插件不读取这些值，仅方便排查「检索相关性」问题）。

## 使用

无需手动操作：

- **检索**：planner 需要回忆时调用 `search_memory`（或 `query_memory`，取决于模式）；对话中正常
  提问即可（如「还记得上次聊的那个项目吗」），planner 会自行决定是否检索；多关键词请拆成多次
  提问（单主题查询命中率更高——这也是给模型的工具使用约定）；
- **日记**：模型觉得有值得记的内容时自行调用 `write_diary`；之后检索相关主题时日记会以
  `[日记] 2026-09-18 21:30 内容…` 的形态出现在检索结果里（本地时间）。

聊天指令（无权限时**静默不回复**。权限判定与宿主 `plugin.permission`
操作员名单（格式如 `qq:123456789`）及单命令放行规则（`plugin.command_permissions`）同源，
也可在本插件 WebUI「日记」页配置**管理员 QQ**（`diary.admin_qqs`，纯 QQ 号）直接放行，
本地控制台默认放行）。`/日记` 仅查看当前聊天流的日记；`/删日记` 的删除列表为**全部**日记
（跨流，便于删除管理）。勾选「通知 LLM 日记被查看」（`diary.notify_context`）时，每次执行
`/日记` 后会把事件注入给模型（**planner 与 replyer 各一次**，只作用于当次请求、不写入聊天历史）：
插件用 `message.get_recent` 直读最近原始消息，绕过宿主对指令/回复的过滤，把「用户刚发送的
指令原文（如 `/日记`）+ 被查看的日记条目正文」作为内部参考消息注入——planner 阶段
看到后可能自行调用 `search_memory` 关联回忆，replyer 阶段让回复里带着「知道自己日记被看过」：

| 指令 | 作用 |
|---|---|
| `/日记 [条数]` | 按时间正序返回当前聊天流的模型日记（默认 10 条，上限 50），用真实日记口吻书写（`2026年9月22日 星期二 下午4点 内容`，同一天后续只写时间） |
| `/删日记` | 返回**全部**日记列表（跨流，带来源标注），带编号供下一步按编号删除 |
| `/删日记 <编号>` | 删除指定编号的日记（按编号全局删除，可删任意流的日记），删除后回显内容摘要 |

## 常见问题

| 现象 | 处理 |
|---|---|
| 想删除某条日记 | 发送 `/删日记` 查看带编号的日记列表，再发 `/删日记 <编号>`；想全部清空则手动删除 `diary.db`（见下文「边界与说明」） |
| 发送 `/日记` 无任何回复 | 指令需权限而无权限时静默不回复：把你的 QQ 加入本插件 WebUI「日记」页的**管理员 QQ**（`diary.admin_qqs`），或加入宿主配置 `plugin.permission`（格式如 `qq:123456789`），或为 `github.elmeir.memory-enhance.diary_list` / `diary_delete` 配置单命令放行 |
| 日志出现「检测到重复工具名」，检索行为未变化 | 仅「替换原生」模式会遇到：宿主内置 query_memory 未禁用；按「安装」说明关闭后重启（或改用默认的新增工具模式） |
| 想让模型知道自己日记被看过 | 勾选 WebUI「日记」页「通知 LLM 日记被查看」（`diary.notify_context`）；每次 `/日记` 后会把“刚有人查看了你的日记（编号+摘要）”注入下一条模型回复（一次性，不入聊天历史） |
| 模型没有使用 search_memory | 工具已随列表常驻；多为模型自行判断无需检索。可在宿主提示词中引导「回忆往事时先检索记忆」 |
| 其它会话的记忆搜不到 | 「跨聊天流检索」默认关闭；需要时在 WebUI 切换为「仅群聊」或「全部」 |
| 日记在其它群里被搜到 | 日记同样跟随「跨聊天流检索」：关闭时仅当前流（含无归属旧条目）可见；「仅群聊」时可在群聊范围内被搜到；「全部」时全流可见 |
| 日志出现「事实路未找到 metadata.db」 | A_Memorix 数据目录非默认位置；确认其 `storage.data_dir` 配置后重启 |
| 检索结果为空 | 工具返回「未找到与「xx」相关的长期记忆。」；该范围下尚无相关记忆（记忆由 A_Memorix 摘要管线写入）；可换关键词或确认目标会话已产生记忆 |
| 结果里有不相关的内容 | 宿主「最小保留数」默认 4，会**保底返回**条数（低于阈值的也保留）；收紧方法见下文「进阶」小节——通常只需改 WebUI 一处 |

## 进阶：收紧检索相关性（可选）

正常使用**无需调整**。若检索结果里经常出现明显不相关的内容，可按下面收紧（改动对内置检索工具同样生效）：

| 配置项 | 默认 | 修改入口 | 建议 |
|---|---|---|---|
| 最小保留数（`threshold.min_results`） | 4 | 宿主 WebUI「记忆」页 → 高级 | 调到 **1~2**（最直接，消灭「保底返回」） |
| 动态百分位（`threshold.percentile`） | 75 | WebUI 的配置文件编辑，或手改 `<运行目录>/config/bot_config.toml` 的 `[a_memorix.threshold]`（改后重启） | 调到 **45~55**（阈值更严格） |
| 最小 / 最大阈值 | 0.29 / 0.95 | 同上 | 一般不用动 |

插件配置页的「宿主检索参数」页签会**只读显示**上述各项的当前值。配置页另有「调试」页签：诊断日志开关（检索范围解析 / 群聊流缓存状态）+ 三张「工具信息」卡片（search_memory / query_memory / write_diary 的 LLM 视角定义：可见性 / 描述 / 参数，只读、随插件加载自动刷新）。

## 工作原理

- **段落/关系路与经历路**：经宿主能力 `knowledge.search` 检索（mode=search / episode）；
  关闭 = 当前流单次调用（`respect_filter=true`，尊重记忆过滤策略）；仅群聊 = 当前流 +
  全部群聊（`chat.get_group_streams` 枚举）逐流并发检索后合并去重；全部 = `chat_id` 置空
  的单次全库调用（宿主语义 `scope=None` 即不过滤，与宿主启发式记忆召回同款）；
- **事实路**：`sqlite3` 只读（`mode=ro`）直读 `data/a-memorix/metadata/metadata.db` 的
  `fact_claims` 表——只取 `active` 状态、过滤 `valid_to` 已过期项；范围上
  person 级事实视为全局知识（与宿主 `query_person_profile` 同语义）、chat 级事实
  按检索范围过滤（关闭/仅群聊=范围集合，全部=不限）；LIKE 匹配后按命中词数 →
  可信度 → 最近确认时间排序；
- **日记路**：本插件自有 SQLite（`data/plugins/github.elmeir.memory-enhance/diary.db`），
  `write_diary` 追加写入（Unix 时间戳 + 内容 + 聊天流归属）；检索范围跟随「跨聊天流」
  （关闭=当前流；仅群聊=当前流+全部群聊；全部=全流）；按关键词匹配、命中多者优先、
  同分按时间倒序，渲染为 `[日记] 本地时间 内容`；
- **工具接入**：两个检索工具均以 `visibility="deferred"` 为基态声明，planner 钩子按配置补回
  常驻定义（`standards/host-behavior.md` §11/§12 的既有手法，reply-control 的 `select_emoji`
  为先例）；「新增工具」模式下钩子还会从列表移除内置 `query_memory`（LLM 看不见就不会调用）；
- 四路结果按源标注（`[日记]` / `[事实]` / `[记忆]` / `[经历]`），事实命中优先置顶。

## 边界与说明

- 「替换原生」模式的前提是内置工具已禁用；插件无法自行禁用内置工具（宿主 `config.*` 能力只读）——
  默认的「新增工具」模式不依赖宿主开关；
- 接管同名工具时，内置版的两个内部增强（查询反馈纠错、replyer 记忆参考透传）不随接管保留；
- 日记是本插件自有数据（独立于宿主记忆库），卸载插件不删除；想清空可手动删除 `diary.db`
  （重启后自动重建空库），删除单条请用 `/删日记 <编号>`；
- 跨聊天流检索会读取其它会话的记忆，属隐私敏感能力：默认关闭、需显式切换；「仅群聊」不含其它私聊（私聊记忆在任何模式下都不跨流）；
- 事实路为只读直读，不触碰 A_Memorix 的写入事务；库结构变化（如字段重命名）只会
  导致该路跳过并提示，不影响其余路。
